# V0.6.9 File, Productivity & Stability Design

## Goal
Make Drawing Studio safe for real work before animation by introducing a versioned `.drawstudio` project format, direct local-file commands where supported, safe browser fallbacks, autosave/recovery, dirty-state tracking, and a foundation for recent projects and multi-document work.

## Architecture
1. A pure persistence layer owns project schema/version validation and typed-array encoding. It must not depend on the DOM.
2. `DrawingCanvas` exposes explicit export/import document DTO methods instead of leaking private surface maps.
3. `ProjectController` coordinates New/Open/Save/Save As, File System Access API feature detection, upload/download fallback, dirty state, and recent metadata.
4. `AutosaveStore` uses IndexedDB only for recovery/checkpoints and metadata. Local user-owned `.drawstudio` files remain the canonical project store when direct file access is available.
5. Existing drawing behavior, undo/redo, export PNG, and workspace preferences remain independent from persistence.

## Project format v1
A `.drawstudio` file is UTF-8 JSON containing:
- magic: `drawing-studio-project`
- formatVersion: `1`
- appVersion
- metadata: title, createdAt, modifiedAt
- canvas: width, height
- editor state with typed brush texture bytes encoded safely
- layer document metadata
- raster/background content and masks as base64 RGBA payloads
- vector strokes
- selection-layer masks
- extension object reserved for later Text/Manga/Smart Effect/Animation data without breaking format v1 readers

Unknown extension fields must survive validation when possible; unsupported future `formatVersion` values must be rejected explicitly.

## Save strategy
- If `showOpenFilePicker` / `showSaveFilePicker` are available in a secure, user-gesture context, Open/Save/Save As operate on a user-owned `.drawstudio` file handle.
- Otherwise Open uses a normal file input and Save As downloads a `.drawstudio` file.
- Save without an existing writable handle falls back to Save As.
- PNG export remains separate from project Save.

## Autosave / recovery
- IndexedDB stores a bounded latest recovery checkpoint and recent-project metadata.
- Autosave is debounced after dirty changes and never replaces a user-owned file silently.
- Successful explicit Save updates the clean baseline and may refresh the recovery checkpoint.
- Corrupt or incompatible autosaves fail closed with a recoverable error message.

## Dirty state
The app tracks a monotonic document revision. Import/open/save establishes a clean revision; document mutations mark the tab dirty. UI state-only actions such as zoom/pan do not mark project content dirty unless they are deliberately part of project metadata.

## Recovery constraint for this session
The persisted conversation artifact for V0.6.7–V0.6.8.4 was an empty ZIP. Work therefore starts from the verified V0.6.6 source snapshot. Persistence code must be extensible so recovered/reintroduced later node kinds and extension data can be stored without another format rewrite.
