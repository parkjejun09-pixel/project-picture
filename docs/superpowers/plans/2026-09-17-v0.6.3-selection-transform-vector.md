# V0.6.3 Selection, Transform & Vector Complete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the editor's selection, transform, and vector-editing foundations so irregular selections, interactive transforms, and editable vector paths work as real document operations.

**Architecture:** Extend pure drawing modules first (`selectionMask`, `transform`, `vector`) and keep UI wiring in `DrawingCanvas`/`PropertiesPanel`. Selection remains a byte mask plus derived bounds; raster transforms render from an immutable captured source into the active layer; vector paths gain explicit anchor/Bezier handle data while preserving backward compatibility with existing simple points.

**Tech Stack:** TypeScript, Canvas 2D, DOM Pointer Events, Node test runner used by `scripts/test.mjs`.

**Spec:** `docs/product/ROADMAP.md` section `V0.6.3 — Selection, Transform & Vector Complete`

## Global Constraints

- Preserve all existing V0.6.2 behavior and pass the full test suite.
- No fake toolbar controls: every visible V0.6.3 control must call a real operation.
- Raster selection operations must respect document bounds and retain an accurate selection mask.
- Transform operations must be undoable as one history mutation.
- Vector edits must remain editable after drawing and participate in existing history/compositing/export.
- Keep the V0.6.1 UI layout intact; V0.6.3 adds contextual controls rather than redesigning the shell.
