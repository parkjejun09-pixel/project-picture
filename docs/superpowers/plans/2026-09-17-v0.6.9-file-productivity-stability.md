# V0.6.9 File, Productivity & Stability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safe versioned project-file system with direct local file access when supported, browser fallback, recovery autosave, dirty-state tracking, and product-level file commands.

**Architecture:** Keep serialization pure and versioned; expose document DTOs from `DrawingCanvas`; coordinate file handles and UI through a small controller; isolate IndexedDB recovery from canonical file storage. Every checkpoint remains independently testable.

**Tech Stack:** TypeScript, Canvas 2D, DOM File APIs, File System Access API feature detection, IndexedDB, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-17-v0.6.9-file-productivity-stability-design.md`

## Global Constraints
- Runtime dependencies remain zero.
- `.drawstudio` v1 is UTF-8 JSON and rejects unsupported future format versions.
- PNG export remains separate from project Save.
- File System Access API is optional and feature-detected.
- IndexedDB is recovery/fallback metadata, not the only canonical project store.
- New persistence APIs must remain extensible for V0.6.7+ Text/Manga/Smart Effect and V0.7 Animation data.
